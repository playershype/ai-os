Cómo crear la versión de cada cliente

Todas las versiones usan el mismo código. Lo único que cambia entre José y Luis es la marca: nombre, logo, colores, tipografía e ícono. Todo eso vive en un solo archivo, marca.json, más los íconos.

1Diseña la marca

  1. Abre el Creador de marca: https://TU-USUARIO.github.io/ai-os/marca.html (o abre marca.html desde tu copia publicada).
  2. Escribe el nombre de la app y el nombre corto (el que sale debajo del ícono).
  3. Elige el color principal, la tipografía, el idioma (español o inglés) y el formato de hora (12 o 24 horas).
  4. Si el cliente tiene logo, toca Elegir… y súbelo (cuadrado se ve mejor). Si no, se usan sus iniciales.
  5. Mira la vista previa en modo oscuro, modo claro y el ícono. Si aparece un aviso amarillo, léelo: la app ajusta sola el tono para que el texto se lea bien.
  6. Toca Descargar paquete de marca (.zip). Se descarga marca-NOMBRE.zip.

2Crea la copia del cliente

  1. En GitHub, entra a github.com/new y crea un repositorio nuevo con el nombre del cliente, por ejemplo agenda-jose (marca Public) → Create repository.
  2. Toca uploading an existing file y sube todos los archivos de la app (el contenido de la carpeta ai-os-web), igual que en la guía principal → Commit changes.
  3. Vuelve a tocar Add file → Upload files, descomprime el paquete de marca y sube esos archivos (marca.json, manifest.webmanifest, icon-180.png, icon-192.png, icon-512.png y logo.png si existe). GitHub reemplaza los que tienen el mismo nombre → Commit changes.
  4. Activa Settings → Pages → main / root → Save. La app del cliente queda en https://TU-USUARIO.github.io/agenda-jose/.
  5. Recomendado: borra marca.html, MARCAS.html y js/marca-tool.js de la copia del cliente (son herramientas tuyas, no suyas).

3Conecta Google para ese cliente

En la llave de Google (guía principal, paso 4d) agrega la dirección de la nueva copia en Authorized redirect URIs, por ejemplo https://TU-USUARIO.github.io/agenda-jose/. Una misma llave puede tener varias direcciones.

¿Por qué José no puede dañar a Luis?

  • Cada copia es independiente. Cambiar el repositorio de José no toca el de Luis.
  • Los datos usan un espacio lógico separado por marca. Cada marca guarda su información con su propio identificador (el campo “Identificador interno”), por lo que la app no mezcla los datos de una marca con otra. Esto no es una barrera de seguridad entre rutas del mismo dominio: dos apps bajo playershype.github.io comparten el mismo origen del navegador. Para clientes reales, usa dominios o subdominios separados. No cambies el identificador después de entregar la app: la app dejaría de encontrar los datos guardados con el identificador anterior.
  • Cada persona conecta su propio Google. Sus datos sincronizados se guardan localmente en su navegador y el operador de la marca no recibe una copia. Si el usuario activa la IA opcional, el contenido necesario para esa función se envía directamente desde su navegador al proveedor de IA configurado.
Para vender de verdad: lo ideal es un dominio propio con un subdominio por cliente (jose.tumarca.com, luis.tumarca.com). GitHub Pages permite un dominio propio por repositorio en Settings → Pages → Custom domain. Así cada cliente queda totalmente aislado en el navegador y la dirección se ve profesional. Recuerda también la verificación de Google y la política de privacidad, que te expliqué antes.

Actualizar a todos tus clientes

Cuando mejores la app, sube los archivos nuevos a cada repositorio excepto marca.json, manifest.webmanifest, los íconos y logo.png. Así cada cliente recibe la mejora y conserva su marca y sus datos.
